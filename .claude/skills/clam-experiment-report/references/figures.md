# Figures

Figures are generated by `results/make_report_figures.py`, which reads the saved predictions, the
TensorBoard logs and (optionally) the subtype labels, and writes PNGs. Reuse and extend it rather than
writing new plotting code. Its chart style was tuned by inspecting the output, as described below.

## Adding runs

1. Add the run to the `RUNS` dict:
   `key: dict(dir='<run dir name>', name='<display name>', color='<hex>')`.
2. For a per-run report, add the key to the list that loops over single-run figures. That list is
   `ENCODERS` today; if the new run is not an encoder comparison, add a separate list.
3. For a new comparison set, copy the pattern of the existing comparison figures (`fig_encoder_*`,
   `fig_b8_b32_*`), change the list of keys, and give the output files a prefix that names the
   comparison.
4. If the run has a published reference value, put it in a dict like `CLAM_PAPER`, with the source
   in a comment.
5. Run the script from the repo root in the clam env:
   `/var/tmp/shouteng_conda/envs/clam/bin/python results/make_report_figures.py`

## Which figures each report gets (deep-learning reporting conventions)

**Per-run report** (`results/<run>/figures/`):

| File | Shows | Goes in |
|---|---|---|
| `roc_pr.png` | ROC + PR: thin line per fold, mean, ±1 SD band, chance lines | §5 after the per-fold table |
| `per_fold_metrics.png` | dot per fold for AUC/Acc/bACC/Sens/Spec/F1 + mean ± SD | §5 |
| `confusion_subtype.png` | pooled confusion matrix (counts + row %) + detection rate by subtype (pooled bars, fold dots) | end of §5 |
| `training_curves.png` | train loss, val loss, val AUC per epoch; folds thin, mean thick, dots at the best epoch, line at the min. stop epoch | top of §7 |
| `val_vs_test_auc.png` | one dot per fold, labeled with the fold index, diagonal, r in the title | end of §7 |

**Comparison sections and reports** (`results/figures/`):
- grouped metric bars (mean ± SD);
- per-fold AUC with the runs side by side, connected within a fold;
- mean ROC/PR curves by run;
- detection rate by subtype by run;
- one confusion matrix per run;
- mean training curves by run;
- paired-difference forest plot (95% t-CI, filled marker = Wilcoxon p < 0.05) on a **shared x-axis**;
- val-vs-test AUC by run;
- cost bars (time per epoch, total time, storage — separate panels, never two y-axes);
- for a published reference: a gray bar or horizontal reference line.

## Style rules (and the reason for each)

- **One color per entity, fixed across every figure and report.** Readers learn "UNI is orange". The
  colors used so far are ResNet-50 `#2a78d6` (blue), UNI `#eb6834` (orange), CONCH `#1baf7a` (aqua),
  ResNet-50 B = 8 `#86b6ef` (a light step of the same blue, because it is a variant of the same
  entity), and published reference `#898781` (gray, because it is context, not one of our runs).
  For new entities, take the next slots of the dataviz skill's reference palette in order: yellow
  `#eda100`, magenta `#e87ba4`, green `#008300`, violet `#4a3aa7`, red `#e34948`. Load the `dataviz`
  skill for anything beyond this.
- **Same scale when panels are compared.** The paired-difference panels share an x-axis. Separate
  scales made a ±0.002 difference look as large as a 0.05 one.
- **Mark a truncated y-axis** in a footnote ("The y-axis starts at 0.6").
- **Legends and footnotes go below the plots**, through the figure-level `legend_below()` / `note()`
  helpers that `save()` places after `tight_layout()`. An axis-level legend outside the plot squashed
  the panels.
- **No dot may hide another.** Offset paired points horizontally, and connect them with a thin gray
  line.
- Thin marks, hairline solid gridlines, light surface `#fcfcfb`, text in ink colors (never in the
  series color), a numeric minus sign (−) in labels, and no dual axes.
- Interpolated precision for mean PR curves is the running max along the arrays returned by
  `precision_recall_curve`, because recall is decreasing there. Accumulating in the other direction
  produced a flat line at 1.0.

## Always look at the output

After rendering, open every PNG with the Read tool and check it for:
- squashed or empty panels;
- overlapping labels or legends covering data;
- dots hidden behind other dots;
- curves that are obviously wrong (flat at 1.0, outside [0, 1]);
- clipped markers at the axis limits;
- titles that are cut off.

Fix the script, re-render, and look again. Only then insert the figures into the reports.
